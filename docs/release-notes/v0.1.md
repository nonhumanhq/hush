# hush v0.1 release notes

hush keeps private names out of records that may become public. v0.1 is the first release: it replaces the interim scanner (`reference/interim-hush/`) and implements ADR-001 (what hush is) and ADR-002 (what hush matches), as accepted. `docs/migration.md` takes you from the interim scanner to hush.

Flagged tokens in these notes are written apart, as the ADRs write them, so the notes scan clean.

## What v0.1 is

- **One Go module, standard library only:** `github.com/nonhumanhq/hush`. Importers pin an exact version; hush stays at v0.x while its API settles, and every change to the API, the output or the exit codes is listed in these notes.
- **A public package, `hush`,** at the module root (ADR-001 section 7): destinations (`Public`, `Private`, `Client`), `LoadTermSets`, `Config` and `New`, the scans (`ScanBytes`, `ScanReader`, `ScanTree`, `ScanIndex`, `ScanRange`), findings with path redaction, `Report` with `WritePlain` and `WriteJSON`, `WriteErrorJSON`, and a closed table of errors. Every scan returns a clean report, a report and a `*FindingsError`, or an `*Error` and no report, so `if err != nil { return err }` fails closed. `go doc` shows two runnable examples, a buffer and a range.
- **The command line, a thin layer over the package:**
  - `hush scan --destination DEST [--terms FILE | --generic-only] [--identities ADDR[,ADDR...]] [--format plain|json] TARGET`, where `DEST` is `public`, `private` or `client:LABEL`, and `TARGET` is paths, `--index`, `--range REVS` or `--stdin`;
  - `hush hooks install [--force] [--terms FILE] [--identities ADDR[,ADDR...]]` and `hush hooks uninstall`, which write and remove the `pre-commit`, `commit-msg` and `pre-push` hooks;
  - `hush gh --destination DEST [--terms FILE | --generic-only] [--identities ADDR[,ADDR...]] -- GH-ARGUMENTS`, which scans what a `gh` command would post and runs `gh` only after a clean scan;
  - `hush version` and `--help`.
- **Exit status:** 0 clean, 1 findings, 2 an error, with exactly one `hush: ` line on standard error. Messages cite argument positions, never values.
- **Output:** the plain format, one `WHERE:LINE: RULE` per finding, or one JSON document (`hush.scan/1`, ADR-001 section 6.3), written once at the end. No output, error or formatted value holds matched text, a term, a client label or the term file's path (ADR-001 section 6.6).

## Term files: format 1

v0.1 reads **term-file format 1** (ADR-002 section 1.6) and no other. Format 1 is the interim format plus:
- an optional first line `#hush-terms 1`; any other `#hush-terms N` is refused (`unsupported format`);
- header attributes: `visible-to=LABEL[,LABEL...]` (the clients a set may reach), `case=exact` and `match=word` (ADR-002 sections 1.2, 2.2 and 2.3);
- the refusals of ADR-002 sections 1.1 and 1.5, each with a line number, and the load-time checks of section 1.4 on every set name and client label.

A term file must be a regular file that group and others can neither read nor write, outside every scanned path and every scanned repository, and at most 1 MiB. There is no converter: `docs/migration.md` lists the few edits an interim file may need.

## The rules

The generic tier has three rules (ADR-002 section 4): `id-prefix`, now with the wider pattern of section 4.1 (an uppercase letter, then uppercase letters, digits or underscores, a hyphen and digits) and the same built-in allowlist; `ip-address`; and `email-address`, with the identity allowance `--identities` (`Config.Identities`), which lets a listed address pass only where it stands as an identity: an author, committer or tagger line, or a trailer.

## Requirements

- **Go:** `go.mod` names `go 1.26` and no toolchain (HSH-11/D5). CI runs that release and the newest one.
- **git 2.44 or later** for index and range scans (HSH-11/D6), because hush passes `--no-lazy-fetch`. With an older git, every index and range scan exits 2 with `git is missing or older than 2.44`, so the `pre-commit` and `pre-push` hooks refuse every commit and push.
- `sh` for the hooks; `gh` on `PATH` for `hush gh`.
- **Size limits,** each an exported constant (HSH-11/D4): a term file over 1 MiB (`MaxTermFileSize`), a file, blob, standard input or buffer over 64 MiB (`MaxInputSize`), a line over 4 MiB (`MaxLineSize`), and one git command's output over 512 MiB (`MaxGitOutput`) each exit 2 with code `read`. Nothing is skipped.

## Changes from the interim scanner

- **Every call site names its destination and coverage,** or hush exits 2 (ADR-001, Consequences). `docs/migration.md` maps each command.
- **Standard error** holds one `hush: ` line from the message table on exit 2, where the interim printed `hush-interim: ` and its own wording.
- **No partial output on error** (HSH-11/D17): findings are written once, at the end. When a scan fails after findings, standard output stays empty.
- **Intended differences in exit status or output** (HSH-11/D45), each pinned by the comparison test: the wider `id-prefix` pattern; format 1's header attributes, which load, and a set name that holds a term, which is refused; a term file that group or others can read, which is refused; `--range --stdin`, refused; and a directory that cannot be read, reported as `unreadable` (exit 1) where the interim exits 2.
- **Ranges** take no `rev-list` options. hush resolves each revision and selector itself, scans annotated tags as objects of their own, and scans commit and tag headers but `tree`, `parent`, `object` and `type`, with signature blocks skipped (HSH-11/D15, D55). A range that reaches a shallow boundary, a repository with `info/grafts`, and a ref whose target is not a commit each exit 2.
- **Index scans** read stage 0 only (HSH-11/D19) and refuse a missing `GIT_INDEX_FILE`.
- **git** runs with a fixed environment, nothing inherited, `--no-replace-objects`, `--no-lazy-fetch` and fsmonitor off, and its standard error is discarded (HSH-11/D51).
- **Tree scans** report a FIFO, socket, device or unreadable directory as `unreadable` and scan the rest; a path that cannot print safely prints as `<redacted>` with `unreadable in path`.

## Known limits in v0.1

Each limit below is a place where hush v0.1 lets text through or fails open. Remedies are given where there are any.

### Closed standard descriptors (HSH-5/D17)

When hush starts with a standard descriptor closed, the Go runtime opens `/dev/null` in its place, and hush does not tell the two apart:
- with `--stdin` and standard input closed, hush scans nothing and exits 0, so it **fails open**;
- with standard output closed, the findings are lost, but the exit status still reports them.

The human's review of PR #9 kept this unchanged in v0.1. Callers pass a real standard input to `--stdin`.

### Where the address rules let an address through

The review of PR #11 found these, beyond the known misses ADR-002 section 4 lists under each rule. Each example below exits 0 with `--generic-only` (pinned by `TestReleaseNotesLimits`):
- **a domain after a reserved address:** in `"x@example.com@" + "buildhost"`, the rule reads the reserved address and lets the host after its second `@` through;
- **a quoted local part that holds an `@`:** `"\"bob@" + "acme.internal\"@example.com"` passes on its reserved domain;
- **a bracketed candidate whose domain is read after its last `@`:** `"<bob@" + "buildhost@example.com>"` passes;
- **an all-letter IPv6 address,** an unlisted miss of section 4.2: `"fdab:" + ":cafe"`, a unique local address, passes because it reads as a word;
- **a hex word joined to an address by a dot,** also unlisted in section 4.2: `"cafe.fd00:" + ":1"` passes;
- **an address joined by two backslashes before its `@`** is not a candidate: `"bob\\\\" + "@acme.internal"` passes, where one backslash is flagged.

The known misses of ADR-002 section 4 also stand, among them lowercase ID keys, keys and addresses split across lines, encoded forms (percent, entities, base64), IPv4 forms other than four decimal groups, and bare addresses whose domain has no dot. The private sets cover client-specific forms until v0.2.

### Term matching

ADR-002 section 2.4's misses: non-ASCII case, separators between words, abbreviation variants, combining marks, invisible and Unicode space characters, look-alike characters and encodings. List each variant that matters as its own term; a variant that differs by an invisible character or a Unicode space cannot be listed in v0.1.

### `hush gh`

- **Payloads GitHub decodes after the scan** (HSH-11/D10): base64 in a `gh api` payload that hush gh does not already refuse (the contents and git blobs APIs and `createCommitOnBranch` are refused), and string escapes inside a GraphQL query, are not decoded, so text behind them is not seen. An endpoint's percent-escapes, with `+` read as a space in its query, and `--input`'s JSON escapes are scanned decoded.
- **A body file on `gh`'s standard input** (HSH-11/D9): that `gh` reads `--body-file -` from standard input comes from `gh`'s help text, not from a check against `gh` itself.
- **Words echoed in messages:** an unknown command or a field's key prints when it passes the stdin label check. Under `--generic-only` no term is known, so a term can print there, as a `--label` value can (HSH-11/D60).

### Hooks and pushes (HSH-9/D1)

- Hooks are per repository: `git push --recurse-submodules` pushes a submodule's commits without these hooks unless hush is installed in the submodule too.
- A merge commit's `mergetag` header, which HSH-9 recorded as not scanned, is scanned from v0.1 on, but for its signature block's base64 (HSH-11/D15).
- A new branch is scanned against the commits the destination advertises under its heads and tags. A commit advertised only under another ref is scanned again, never skipped. About 3,200 distinct advertised commits exceed one argument's 128 KiB, and the push then fails closed.
- A `--receive-pack` option or `remote.<name>.receivepack` aimed at another repository is not seen, since `ls-remote` asks the URL pushed to.
- With an editor, `commit-msg` also scans git's comment lines, which name the branch and the staged paths (HSH-9's REVIEW.md, finding 3), so a token there blocks the commit. Commit with `-m` or `-F`.

### The formatting guarantee (HSH-11/D38)

It covers `fmt`, `log/slog`, the encoding packages and errors, at any nesting. It does not cover reflection into unexported fields (`reflect.Value.Field` handed to `fmt`, or `reflect.Value.String`) or `unsafe`, which can read any Go value.

### Other limits

- An explicit path argument named `.git` is pruned, so `hush scan ... .git` scans nothing and exits 0, as the interim does.
- hush finds the repository itself and names it to git; `GIT_CEILING_DIRECTORIES` is not honoured, and `core.worktree` is read only to find the work trees for the term-file check (HSH-11/D53).
- A term file in a sibling linked worktree of the scanned repository (another worktree of the same repository) is not refused, and the scan goes on; the file's bytes are still refused once staged or committed there (HSH-11/D53).
- A symlink is scanned as its link text and never followed.

## What v0.2 adds

- **Hostname and secret-format rules** in the generic tier (ADR-001 section 8).
- **Normalization** of terms and text, ADR-002 section 2.5's pipeline: default-ignorable characters removed, compatibility normalization, look-alike folding, Unicode case folding and separator folding. It only adds matches, so every format 1 file keeps its meaning.
- **Scanner mode,** with its own ADR (HSH-13).
